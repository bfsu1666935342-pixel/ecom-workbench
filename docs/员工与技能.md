# 员工（Agent）与技能（Skill）

两个库，各管一件事：

- **技能库**：一个个具体能力（市场机会扫描、Listing 撰写、周报……）。可以单独点开对话，也可以被员工装载。
- **员工**：一个"岗位"，自带几个技能，负责一条业务线的判断和流程。

用户既可以**选员工干活**（省事，员工知道先做什么后做什么），也可以**直接用单个技能**（只想解决一个具体问题）。

## 目录结构

员工放在**技能目录下的 `agents/`** 里，跟着技能一起打包，不需要额外配置：

```
ecom-skills/
├─ skills...  （其实是 skills 根目录下直接放技能目录）
├─ market-scan/
├─ amazon-weekly-report/
└─ agents/
   ├─ selection/
   │  ├─ agent.json     ← 装配清单
   │  └─ AGENT.md       ← 角色说明（拼进系统提示）
   └─ ads/
```

打包时 `agents/` 会跟着 `skills/` 一起进安装包，工作台从 `<安装目录>/skills/agents` 读。

## agent.json

```json
{
  "id": "selection",
  "title": "选品",
  "icon": "🔭",
  "order": 10,
  "tagline": "从一个想法走到能下单的选品决策",
  "description": "负责判断一个类目或产品值不值得做……",
  "skills": ["market-scan", "category-deepdive", "competitor-teardown"],
  "defaultSkill": "market-scan"
}
```

- `skills` 里写**技能 id**（文件夹名）。技能是独立的，加一个 id 就多一项能力，删掉就没了。
- 引用了不存在的技能会被自动忽略，不会报错。
- `order` 决定员工在库里的顺序。

## AGENT.md

写给模型的"岗位说明书"，只写三件事，别重复技能里的细节：

1. **你负责什么**——这个岗位管什么、不管什么；
2. **干活顺序**——什么情况先用哪个技能；
3. **什么时候停下来**——缺数据、碰红线、算不出来时该停。

## 运行时怎么工作

1. 选中员工后，`AGENT.md` 拼进系统提示，同时给模型一份**技能目录**（id + 标题 + 一句话）；
2. 模型需要具体方法时调用 `load_skill(id)` 把那份 `SKILL.md` 装进来——**不是一开始就把所有技能全塞进去**，否则上下文会被稀释；
3. `load_skill` 只能装载这个员工名下的技能，装别的会返回错误；
4. 用户单独选技能时，行为和以前一样：直接注入那份 `SKILL.md`。

## 界面

- 侧边栏「员工」→ 卡片列表，点开能看到岗位技能；
- 卡片里可以**增删技能**，改动直接写回 `agent.json`，热重载生效；
- 「用这名员工开始」→ 新对话，顶部会显示员工标签。

## 加一个新员工

1. 在 `agents/` 下建目录，写 `agent.json` + `AGENT.md`；
2. `skills` 里填你想给的技能 id；
3. 存盘 → 工作台窗口打印「技能已重载：N 个 · 员工 M 名」→ 刷新页面就有。
