# 如何添加 / 修改技能

技能 = 一段写给模型的「岗位说明书」+ 一点界面元数据。放进技能目录后就会出现在左侧技能库（保存即生效，不用重启，见文末「改完怎么生效」）。

## 技能放在哪

技能内容和程序分开维护：程序在这个仓库，技能在 `ecom-skills` 仓库。

```
某个目录/
├─ ecom-workbench/      # 程序
│  ├─ server/ app/ …
│  └─ skills/           # 内置技能（旧版，迁移完成后清空）
└─ ecom-skills/         # 技能库（日常改的是这里）
```

`config.json` 里这一行决定去哪找：

```json
{ "extraSkillsDirs": ["../ecom-skills"] }
```

- 先读内置的 `skills/`，再读 `extraSkillsDirs`；**同一个技能 id 后面的覆盖前面的**。
- 目录不存在就跳过，不会报错（所以对方电脑上没 clone 技能库也能正常启动）。
- 也可以临时用环境变量指定：`set ECOM_SKILLS_DIR=D:\skills;E:\more`（分号分隔）。

打包时 `build.ps1` 会把 `extraSkillsDirs` 的内容快照合并进 zip 的 `skills/`，发出去的包是完整的。

## 目录结构

```
skills/
└─ my-skill/
   ├─ SKILL.md      # 必填：技能说明（给模型看）
   └─ skill.json    # 建议填：标题、分组、常用问法、表单字段（给界面看）
```

`skill.json` 可以省略；省略时用 `SKILL.md` frontmatter 里的 `name`、`description` 和一级标题。界面按分组独立编号（每组 01、02…），不再使用图标。

## skill.json

```json
{
  "id": "my-skill",
  "title": "我的技能",
  "group": "选品与市场",
  "order": 200,
  "tagline": "一句话说明这个技能解决什么问题",
  "description": "点开技能卡片时显示的详细介绍，2–3 句。",
  "starters": [
    "帮我做……",
    "看看这个……"
  ],
  "fields": [
    {
      "key": "product",
      "label": "产品 / 类目",
      "type": "text",
      "placeholder": "例如：便携露营灯，美国站",
      "required": true
    },
    {
      "key": "detail",
      "label": "补充信息",
      "type": "textarea",
      "placeholder": "……"
    }
  ]
}
```

- `id`：英文、短横线，和文件夹名一致最好。
- `title`：左侧技能库和首页索引里显示的名称。
- `group`：左侧分组名；新分组会自动出现。
- `order`：数字越小越靠上；每个分组内从 01 开始独立编号，按 `order` 排序。
- `tagline`：首页索引里的一句话说明。
- `starters`：技能弹窗里的「常用问法」，点击后填入输入框。
- `fields`：会渲染成技能弹窗里的表单；用户填了就会拼进提问。`type` 支持 `text` / `textarea`。
- `status`：填 `dsh-only` 时，独立工作台会跳过这个技能（它需要 DSH 的终端/Python 能力），不在技能库里显示。
- `icon` / `featured`：旧版界面字段，当前版本不再使用，可以删掉。

## SKILL.md

````markdown
---
name: my-skill
description: "用一句话说明什么时候用这个技能，写给模型做路由判断。"
---

# 我的技能

## 适用场景
- ……

## 先收信息
1. ……
2. ……

## 处理流程
### 1. ……
……

## 输出格式

```markdown
## 结论
……
```

## 红线
1. 不编数据。
2. ……
````

`SKILL.md` 的正文会被完整拼进系统提示词（选中该技能时）。写法建议：

- **先收信息**：明确要问哪几项；信息不全时怎么降级处理。
- **处理流程**：分步骤，每步给判断标准或公式。
- **输出格式**：给一个模板，模型会照做，界面也能渲染表格。
- **红线**：不编数字、不承诺结果、合规边界。
- 长度控制在 1500–3000 字；太长会占上下文，太短会空泛。

## 让技能真的「动手」

技能正文里可以直接要求模型使用内置工具：

- `web_search` / `read_url`：联网查资料、读网页（需要用户打开「联网」）。
- `read_file` / `list_files`：读工作区文件（用户上传的附件在 `attachments/`）。
- `write_file`：把结果写成文件，例如 `reports/xxx.md`。
- `run_javascript`：跑 Node 代码做精确计算；内置 `read()`、`readCsv()`、`write()`、`readJson()`、`list()`、`table()`。

例如在 SKILL.md 里写：

> 拿到 CSV 后必须用 `readCsv()` 汇总，先报行数和总花费；再用 `write()` 生成 `reports/诊断结果.csv`。

## 和 DSH 技能兼容

`SKILL.md` 使用标准 frontmatter（`name` + `description`），把整个技能文件夹复制到 DSH 的 skills 目录也能直接被 DSH 识别：

```
D:\.dsh\skills\my-skill\
```

DSH 会读 `SKILL.md` 的正文和 frontmatter；`skill.json` 只影响这个工作台的界面展示。

## 改完怎么生效

**保存即生效**，不用重启、不用重新打包、不用重新下载。

- 修改 `SKILL.md` / `skill.json` 后，服务窗口会打印一行 `[时间] 技能已重载：N 个`。
- 浏览器按 `F5` 刷新即可看到新的技能标题、说明和编号；不刷新也能生效——正文是在对话时读取的，改完直接发消息就是新逻辑。
- 只有改动 `server/` 里的代码才需要重启。
- 想临时关掉自动重载：设环境变量 `ECOM_NO_WATCH=1`。

如果新增后没出现：检查 `skills/<目录>/SKILL.md` 是否存在、`skill.json` 是否是合法 JSON（不能有尾逗号），然后看服务窗口有没有报「重载失败」。

## 技能里怎么调 MCP 数据源

这是「框架」和「能直接带业务」之间最大的差距：只写"用卖家精灵查一下"，模型不知道该调哪个工具；写清工具名和参数，它才会真的调。

1. 在界面左侧「数据源」里配好并「保存并测试」，成功后界面会显示**读到的工具数量和工具名**。
2. 工具名会带数据源前缀，形如 `mcp__sorftime__category_report`。技能里就写这个全名。
3. 在 SKILL.md 里把「先收信息」改成「先取数」，明确写：调哪个工具、传什么参数、拿到结果后怎么校验、查不到时怎么降级。

示例：

> **第 1 步 · 取类目数据**
> 调用 `mcp__sorftime__category_report`，参数 `marketplace=US`、`category=<用户给的一级类目>`。
> 返回后先核对：Top100 条数是否 ≥ 80、价格字段是否为空。条数不足或字段为空时，**停下来告诉用户缺什么**，不要用记忆里的数字补。
> 工具不可用时，降级为：请用户从卖家精灵导出 CSV 上传，再走「读文件」流程。

同一个技能里引用的工具名必须和数据源实际暴露的一致；不确定就先在「数据源」页点「测试」，以那里的工具名为准。
