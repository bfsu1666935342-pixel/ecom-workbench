# 类目深度评估

从“感觉能做”走到“有数据支撑的决策”。所有数字必须能追溯到用户上传的文件。

## 适用场景

- 已经有类目数据，要一份正式评估
- 准备向老板/合伙人汇报，需要可交付报告
- 在 2–3 个类目之间做取舍
- 要评估进入后的产品概念与定价

不适用：只有产品想法、没有数据（先用「市场机会扫描」）；单 ASIN 拆解（用「竞品拆解」）。

## 先盘点数据

让用户上传或粘贴，逐项确认有没有：

| 数据 | 用途 | 没有时 |
|---|---|---|
| 类目 Top100 / Top400 | 销量、价格、品牌、评论分布 | 用卖家精灵导出 |
| 类目月销/月额趋势 | 需求与季节 | 用 ABA 或行业报告 |
| 关键词表 / ABA | 搜索需求、词集中度 | 用关键词工具 |
| Top10 产品详情 | 卖点、评分、变体 | 逐个 ASIN 抓 |
| 差评/评论 | 痛点与改进点 | 抓 Top5 的 1–3 星 |
| 成本/物流/费率 | 单位经济 | 用户提供 |

数据不够时，**先出“数据缺口版”**，不要用估算填满。

## 分析框架

### 1. 市场

- 月销量、月销售额、同比/环比
- 季节性：12 个月曲线，峰谷月份，旺季占比
- 价格带分布：<$15 / $15–25 / $25–40 / $40–70 / >$70 的销量与 SKU 占比
- 需求驱动：功能升级、场景变化、替代品

### 2. 竞争

- CR5 / CR10（按销量或销售额），判断集中度
- 品牌格局：头部品牌、白牌占比、中国卖家占比（有数据才算）
- 评论壁垒：Top10 评论中位数、上架时长、新品占比
- 广告密度：搜索结果前 3 页广告位占比（需实测/截图）
- 价格战信号：长期折扣、Coupon、频繁秒杀

### 3. 产品与评论

- Top10 的卖点、规格、变体、定价
- 评论痛点聚类：质量、尺寸、说明书、耐用、售后、预期落差
- 机会点：未被满足的场景、可感知的结构改进、可证明的参数

### 4. 关键词

- 核心词、长尾词、场景词
- 搜索集中度：前 5 个词占多少搜索
- 标题覆盖缺口：Top10 没覆盖但搜索量可观的词

### 5. 单位经济

用用户成本做单件 P&L：

`售价 - 采购 - 头程 - FBA - 佣金 - 退货 - 仓储 - 广告 = 净利`

- 给出盈亏平衡 ACOS
- 做价格 × 广告占比的敏感性表
- 标出所有假设，不混入“实测”

### 6. 结论

- 三档：进入 / 有条件进入 / 不进入
- 如果进入：3 个产品概念（人群 + 差异 + 价格带 + 为什么现在）
- 如果暂缓：缺什么数据、验证成本多少

## 交付物

优先输出一个**自包含 HTML 报告**，用 `write_file` 写到 `reports/<类目>-category-report.html`，要求：

- 单文件，无 CDN、无外部字体
- 顶部：类目、站点、数据时间、样本量、数据来源声明
- 6 个区块：市场 / 竞争 / 价格 / 产品与评论 / 关键词 / 单位经济
- 关键数字用卡片，趋势用 CSS 柱状/折线（SVG 手绘即可），不要引第三方图表库
- 每个结论旁边标数据来源；缺失项单独列「数据缺口」
- 移动端可读，打印友好

同时在对话里给 10 行以内的结论摘要，不要把整份报告贴进聊天。

## 红线

1. 不编数据；没有的模块写“缺失”，不静默估算。
2. 第三方数据（卖家精灵/Sorftime）不是亚马逊官方，报告里必须声明。
3. 假设与实测分开标注。
4. 一个类目一份报告，不混用其他类目的结论。
5. 样本 < 30 个 ASIN 或不足 12 个月时，结论降级并提示样本偏差。
