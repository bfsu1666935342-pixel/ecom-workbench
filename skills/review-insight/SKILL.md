# 差评洞察（VOC）

每一条差评都是一个免费的选品/文案线索，前提是别只看情绪。

## 适用场景

- 新品上架前，想知道竞品为什么被骂
- 自家链接评分下滑、退货率高
- 要改产品、改包装、改说明书、改 Listing
- 准备 QA、A+ 对比模块、客服话术

不适用：只看销量数据选品（用「市场机会扫描」）。

## 先收信息

1. 评论文本（直接粘贴，或上传 CSV/Excel，字段：评分、标题、正文、日期、变体）
2. ASIN / 产品
3. 评论数量与时间范围
4. 你的目的：改产品 / 改文案 / 降退货 / 找卖点

评论少于 20 条时，结论只能当线索，不能当统计。

## 分析流程

### 1. 清洗与分层

- 按星级分组：1–2 星（痛点）、3 星（犹豫点）、4–5 星（购买理由）
- 按变体分组：差评是否集中在某个颜色/尺寸
- 按时间分组：近期是否恶化
- 去掉无内容、纯情绪、明显刷评（但不要公开指控）

### 2. 主题聚类

给每条评论打标签，统计频次：

| 大类 | 细分示例 |
|---|---|
| 产品质量 | 做工、材质、异味、耐用、漏水、过热 |
| 规格预期 | 尺寸偏小、亮度不足、电池虚标 |
| 使用体验 | 难安装、说明书看不懂、按键反人类 |
| 物流包装 | 压坏、缺件、慢 |
| 售后 | 联系不上、退换麻烦 |
| Listing 误导 | 图片与实物不符、功能夸大 |

区分：**产品问题 / 文案预期问题 / 物流问题 / 个别瑕疵**。四类解法完全不同。

### 3. 量化

- 每个主题出现次数、占比、平均星级
- 高频主题 × 高星级影响 = 优先级
- 找出“提到就低分”的一票否决项（如安全隐患）

大文件用 `run_javascript` + `readCsv()` 统计，输出频次表，不要凭印象。

### 4. 转成动作

每个高频痛点给一个动作：

- 产品：改结构/改材质/加配件/换供应商
- 包装：加固定、加说明卡、改外箱
- 说明书：重画步骤图、加视频二维码
- Listing：提前说明限制、改图片、加对比表、FAQ
- 客服：预设话术、主动跟进

## 输出格式

````markdown
## 样本
共 xx 条，1–2 星 xx 条，时间范围 xx，变体分布 xx

## 痛点排行
| 主题 | 次数 | 占比 | 平均星级 | 典型原话 | 归因 |
|---|---|---|---|---|---|

## 一票否决项
- ...（有则最高优先级）

## 产品改进（按 ROI）
1. ...（解决 xx% 的差评）
2. ...

## Listing 预防
- 图片：...
- 五点：...
- A+ / QA：...

## 可以放大的好评卖点
- ...（原话）
- 建议写进第 x 点/主图

## 客服话术
- 针对 xx 问题：...

## 数据缺口
- ...
````

用户要文件时，写成 `reports/<产品>-voc.md`。

## 红线

1. 不编评论、不改原话；引用要标注星级和变体。
2. 不建议刷评、删差评、威胁买家、诱导好评。
3. 不把个别瑕疵说成普遍问题；样本小要说明。
4. 不公开指控竞品刷单，除非有确凿证据（也建议不公开）。
5. 涉及安全/健康问题，建议立即停售排查，而不是只改文案。
